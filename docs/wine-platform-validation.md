# Проверка платформы на истории Wine

Проверка относится к локальному прототипу для одного пользователя. API и интерфейс не исполняют код эксперимента и не подтверждают воспроизводимость. Сервер слушает только loopback и не предоставляет аутентификацию; запускайте его и храните каталог только в доверенной локальной среде. ADR сохраняют статус proposed.

## Воспроизводимая демонстрация

Нужны Git с доступом к публичному core, Go версии из go.mod, Python 3, Node.js 24.21.0 и npm 11.19.0. Команда создаёт новый рабочий каталог, поэтому родитель должен существовать, а сам каталог — отсутствовать:

```sh
python3 tools/wine_demo.py --work /path/to/new-wine-demo
cd web
npm ci
npm run build
cd ..
go build -o /path/to/platform ./cmd/platform
/path/to/platform --store /path/to/new-wine-demo/store --web-dir web/dist/browser --listen 127.0.0.1:8080
```

Скрипт клонирует полную историю публичного core, фиксирует commit `5c37e250896fbb67670e7a1897853f78baec144d` и до выполнения сравнивает все файлы с объектами Git. Для автономного источника полной истории можно передать `--core-source /path/to/core-git`. Проверяются 27 хешей публичного набора issue20 и пять файлов выходов по размеру и SHA-256. SHA-256 самого манифеста: `80efe042b78f51d01b3be1cc39d5928ec3893e563d1267945fc643835872744c`. Проверяется связь исходного запуска, снимка и повтора. Тело запроса повтора сверяется с записью после сортировки outputs по path — эту нормализацию выполняет ядро; остальные значения и поля должны совпасть.

Импорт регистрирует сохранённый исходный запуск и восстанавливает запись повтора из публичных свидетельств как caller-reported. Меняются идентификаторы каталога и текст свидетельств наблюдений; исходные UUID пайплайна, байты выходов и прошедшие времена сохраняются. Соответствие идентификаторов и изменённые поля записаны в `demo-metadata.json`. **Новое обучение и проверка текущей среды не выполняются.** Без wheelhouse семь внешних обязательных зависимостей остаются unchecked, поэтому материалы не готовы. `--wheelhouse /path/to/wheels` передаёт заранее подготовленные wheels в импортёр core; загрузки пакетов демонстрация не выполняет. Даже при наличии wheels статусы runtime, execution и numerical agreement в плане остаются unchecked.

Скрипт также создаёт отдельный пустой каталог и полную копию хранилища с удалённым проверенным обязательным входом. Исходное хранилище сверяется по хешам до и после. Существующие рабочие каталоги, пересекающиеся пути и символические ссылки в пути рабочего каталога отклоняются; ошибочная операция не перезаписывает ранее созданную работу.

## Проверка API и интерфейса

Установите Chromium для Playwright (`cd web && npx playwright install chromium`) и выполните из каталога web:

```sh
WINE_WORK=/path/to/new-wine-demo WINE_PLATFORM=/path/to/platform \
UI_EVIDENCE_DIR=/path/to/new-screenshots node scripts/wine-smoke.mjs
```

Проверяются реальные Go API и собранный Angular: исходный запуск и повтор выбираются по ID, проверяются их связи, четыре метрики, сравнение и план. Отдельно проверяются пустая история и предупреждение missing на копии. Скриншоты остаются в указанном локальном каталоге. Для проверки имеющегося реального хранилища можно задать `WINE_HISTORICAL_STORE`; используются исторические ID из метаданных публичных свидетельств, хранилище открывается только для чтения. Перед проверкой и после неё следует самостоятельно сравнить хеши файлов.

В локальной проверке 2026-11-11 сценарии реконструкции, пустого каталога и missing прошли в браузере с настоящим API. Отдельно успешно просмотрена история ранее выполненного цикла Wine: исходный запуск, повтор, их связь, метрики, сравнение и план. Все 28 файлов исходного хранилища сохранили прежние SHA-256. Это проверка отображения сохранённых данных, а не новое испытание обучения. Для нового полного цикла используйте `examples/wine_catalog/validate_cycle.py` из core: нужны совместимые CPython 3.12.15, Linux x86_64, семь wheels и совпадающий полный fingerprint; несовпадение среды не является успешным восстановлением.
